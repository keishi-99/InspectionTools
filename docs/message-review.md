# 画面に出すメッセージの見直し(手順5-5b)

作業者に見える通知・確認の文面を洗い出し、問題点と直し方の案をまとめる。直すのは、案の採否を決めたあと(5-5d)。

見る基準は次の3つ。
- 何が起きたかが分かる。
- 次に何をすればよいかが分かる。
- 内部の言葉(英語の例外、役割名の英字)が、そのまま出ていない。

## A. 直したほうがよいもの(優先度: 高)

| # | 場所 | 状況 | いまの文面 | 問題 | 案 |
|---|---|---|---|---|---|
| A1 | `MainViewModel.Save` | 途中保存に失敗した | 「途中保存に失敗しました。検査は続けられますが、アプリが終了すると結果が失われます。」+ 例外の文 | **項目を進めるたびに保存するので、失敗が続くと、毎回ダイアログが出る**。確定のたびに止まる | 最初の1回だけ出し、保存に成功するまで再表示しない(成功したら元に戻す) |
| A2 | `MainViewModel.RunInstrumentOperationAsync` | 値の取得に失敗した | 「値を取得できませんでした。」+「DMM01…: 測定値を取得できません。…」+「手入力で続けるか、**「設定を再適用」**でやり直してください。」 | (1)「取得できません」が2回出る。(2)値の取得の失敗に、「設定を再適用」は対応しない | 取得の失敗: 「もう一度「値を取得」を押すか、手入力で続けてください。」。設定の適用の失敗: 今の文のまま。見出しと詳細で同じ言葉を繰り返さない |
| A3 | `InstrumentController`(未接続) | 接続していない役割を使おうとした | 「`{role}` の測定器が接続されていません。」 | 役割名が英字の識別子(`Dmm01` など)のまま出る | 他の文と同じ表記(`Describe(role)`)にそろえる |
| A4 | `MainViewModel.Start` | 途中保存を復元できなかった | 「理由: 製品が違います: … / 項目数が違います: 56(保存時) / 54(現在)」 | 作業者には、理由の意味が分からない(定義ファイルを直したため、という説明がない) | 理由の下に、「製品の定義(項目)が変わった可能性があります。保存してあった結果は使えません」と添える |
| A5 | `WpfDialogService.ShowInfo` | 「検査を中断しました」を出す | ウィンドウの題が「**完了**」 | 中断なのに「完了」と出る | 題を「お知らせ」にする(転記完了だけ「完了」にしたければ、呼び出し側で題を渡す) |
| A6 | `App.xaml.cs`(キー割り当て)、`MainWindow`(ホットキー) | 設定の注意を知らせる | `ShowError` で、題は「**エラー**」、赤い×のアイコン | 起動は続けられるのに、エラーに見える。作業者が不安になる | 警告用の通知(`ShowWarning`、題「確認」、黄色の!アイコン)を追加する |

## B. 直すと分かりやすくなるもの(優先度: 中)

| # | 場所 | いまの文面 | 案 |
|---|---|---|---|
| B1 | `CommitValue`(数値でない入力) | 「数値で入力してください。」 | 入力された文字を添える(例: 「'1.2.3' は数値として読めません。例: 1.234」) |

| B4 | `InstrumentConnectionException` | 「測定器に接続できませんでした。\n・…\n・…」 | 最後に「接続を解除しました。選び直して、もう一度接続してください。」を添える |

## C. このままでよいもの

- 多重起動(「すでに起動しています。起動中のアプリを使ってください。」)
- 台数の上限(「{製品} の台数は最大 {N} 台までです。」)
- 結果が消える台数の削減の確認、未実施の項目の確認、合格範囲の食い違いの確認
- 途中保存の再開の確認(「続きから再開しますか？」)
- 転記の完了、転記後の途中保存を削除できなかったときの案内
- テンプレートが別の製品のときの文(「…別の製品のテンプレートではありませんか」)
- キー割り当ての各警告、測定器の一覧(`VisaAddress.xml`)の各警告

## D. 作業者には出ない(開発・設定ミスの検知)

定義ファイルや設定の書き間違いで出る文は、書いた人向けなので、今のままでよい。
- `ProductDefinitionLoader` の各文、`InspectionItem` の各文、`KeyBindingLoader` の各文

ただし1つ、**検査中にアプリが落ちうる点**がある。
- `ProductProcedure.FindAction` は、製品の定義ファイルの `actionId`(null でないもの)が手順表にないと `KeyNotFoundException` を投げる。この例外は誰も捕まえない。手順表のある製品で、現在の項目の動作を調べる箇所(測定器に接続しているときの、項目を移動したあとの状態適用 `ApplyCurrentItemActionAsync`、「値を取得」、キー案内の更新など)から出る。接続していれば、状態を適用する前に失敗する。製品を選んだ時点や、アプリを終了するときには出ない。
- いまは、EL5000AC の定義と手順表の対応を、テストで確認している。ただし、定義ファイルを直した人が、テストを実行しないで配ると起こりうる。
- 案(E1): 製品を開くとき(`SelectProduct`)に、すべての `actionId` が手順表にあることを確認し、なければ「定義の `actionId` が手順表にありません: …」と知らせてメニューに戻る。

## 対応状況(手順5-5d)

| # | 状況 | 対応 |
|---|---|---|
| A1 | 対応済み | 途中保存の失敗は、続けて失敗しても、最初の1回だけ通知する。保存できたあとの失敗は、また通知する |
| A2 | 対応済み | 値の取得の失敗には、「もう一度「値を取得」を押すか、手入力で続けてください。」を出す。設定の適用の失敗は、「設定を再適用」の案内のまま。同じ内容を2回書かない |
| A3 | 対応済み | 測定器が接続されていないときの文面も、他の文と同じ表記(`Describe`)にそろえた |
| A4 | 対応済み | 復元できなかったときに、「製品の定義(項目)が変わったか、保存ファイルが壊れた可能性があります。保存してあった結果は使えません。」を添えた |
| A5 | 対応済み | 通知の題を「お知らせ」にした(転記の完了も、検査の中断も、同じ題) |
| A6 | 対応済み | 警告用の通知(`ShowWarning`、題「確認」、黄色の!アイコン)を追加した。キー割り当ての注意、前面ホットキーを有効にできないとき、設定ファイル(`settings.json`)の読み込みと保存の失敗で使う |
| B1 | 対応済み | 数値でない入力に、入力した文字と例を添えた |
| B2 | 対応済み | 通信の失敗は、「測定器 Dmm02（DMM02）との通信に失敗しました。」の形で、どの機器かを書く(機器の名前が分からないときは、役割名だけ)。続けて「ケーブルと電源を確認してください。」を書き、英語の詳細は「（詳細: …）」に分けた。通信はできたが返事が数値として読めなかったときは、「…の返事を数値として読めませんでした。」と書き、通信の失敗とは書かない |
| B3 | 見送り | 転記の失敗は、今のままでよい |
| B4 | 対応済み | 接続の失敗の最後に、「接続を解除しました。選び直して、もう一度接続してください。」を添えた |
| B5、B6 | 見送り | 今のままでよい |
| E1 | 対応済み | 製品を開くとき、定義の `actionId` がすべて手順表にあるか確かめ、なければ項目名を添えて知らせてメニューに戻る |
